# Native backend (phase 3, M4)

How `pythrust build` works, what it covers today, and the order the rest lands in. Decisions behind it: [research/backend.md](research/backend.md) (Cranelift, AOT) and [research/ir.md](research/ir.md) (one CFG IR, `pythrust-rt`).

## Pipeline

```
source -> lex -> parse -> infer -> lower -> ir::Program -> codegen -> object -> system linker + pythrust-rt -> executable
```

| Piece | Where | Does |
|---|---|---|
| IR | `pythrust-compiler/src/ir.rs` | Contract type. Basic blocks over typed, monomorphic locals; not SSA. |
| Lowering | `src/lower/` | Typed AST to IR. Monomorphizes generic functions per call-site types; desugars `for` (over `range`, strings and lists), chained compares, `and`/`or`, unpacking; interns list and tuple types; makes reference ownership explicit. |
| Codegen | `src/codegen/` | IR to an object file with Cranelift (`opt_level=speed`, PIC). Checked int arithmetic, Python floor `//` and `%` on ints, and float `+ - * /` and comparisons are emitted inline; `num.rs` holds the numeric rvalues, `seq.rs` lists and tuples. |
| Runtime | `crates/pythrust-rt` | Static library: `main`, buffered stdout, `print` formatting, `pt_fail`, refcounted strings (`str.rs`), float `repr`, `**` and parsing (`num.rs`), lists and tuples (`seq.rs`), the per-thread context and pending exception (`exc.rs`), counts and borrow cells that tasks may share (`sync.rs`). The project's only `unsafe`, each item marked `allow(unsafe_code)` with its reason. |
| Driver | `src/main.rs` | `pythrust build f.pyr` writes `f` (`f.exe` on Windows), linking with the system `cc`, or MSVC's `link.exe` on Windows. |

The compiled binary prints what `pythrust run` prints. A runtime error's message is rendered at compile time (`path:line:col`, source line, carets) and stored in the binary, then printed by `pt_fail`, which flushes stdout and exits 1.

`pythrust build` finds the runtime library (`libpythrust_rt.a`, or `pythrust_rt.lib` on Windows) next to its own executable, where `cargo build` puts it, or at `$PYTHRUST_RT`.

## Covered now

Ints (checked `i64`), floats (`f64`), bools, `None`, strings; top-level functions with positional and keyword arguments (evaluated as written, then bound to parameters) and defaults, reading module variables, recursion and generic instantiation; `if`/`elif`/`else`, `while` and `for x in range(...)` with `else`, `break`, `continue`; `+ - * / // % **`, unary `- + not`, chained comparisons, `and`/`or`, conditional expressions, `is None`; `print` with `sep` and `end`. Numbers follow Python's tower, with a bool computing as the int it is (`True + 1`, `int(True)`, `xs[True]`, `range(True)`, `t < 2`): `/`, or an int meeting a float, computes in floats, and mixed comparisons compare as floats (as `run` does). `int()` of a float or a string, `float()` of an int, bool or string, and `str()` and `print` of a float (Python's shortest `repr`). On strings: literals, `+`, `*` by an int, `s[i]` (negative too), `len`, `str()` of ints, bools and `None`, comparisons in code point order, `in` and `not in`, truthiness, `for ch in s`. Lists and tuples: displays, `xs[i]` and `xs[i] = v` (negative too), `t[k]` by a literal, `xs[i] op= v`, `append`, `len`, `list(xs)` (a shallow copy), `str()` and `print` (Python's `repr`), `==` and lexicographic ordering, `in` on lists (a needle of another type meets each element as `==` does: `1 in [True]`, `True in [1.0, None]`), truthiness, `for` over a list or a tuple (with unpacking in the target), and unpacking a tuple, list or string in assignment (a list or string of the wrong length fails as in Python). Optionals (`T | None`) of every type: passing, returning (falling off an optional function returns `None`), storing in lists and tuples, `is None` / `is not None` and the narrowing inference does, `==` / `!=`, truthiness, `and` / `or`, `str()` and `print`; a value adapts structurally where an optional is declared, so `(None, "a")` passes as a `tuple[int | None, str] | None`. Ranges as values: stored, passed, returned and held in lists; `len`, `r[i]` (negative too), `in` (an int, bool or float), `==` / `!=` (as Python: equal when they produce the same ints), truthiness, `str()` and `print`, unpacking, and `for` over one. Exceptions (phase 4, B3): `raise`, `try` with `except Name [as e]` handlers, the builtin exceptions as values of any argument type but one holding a list that may hold an exception (stored, passed, returned, held in lists, tuples and optionals; `str()`, `print`, `repr` inside a container, `==` by identity), and `int(s)` / `float(s)` raising a catchable `ValueError`; an exception escaping the module prints `run`'s diagnostic at the `raise`. Dicts and sets (M6): displays, `d[k]` (a missing key raises a catchable `KeyError`), `d[k] = v`, `d[k] += v`, `set.add`, `dict.get`, `in`, `len`, truthiness, `==` / `!=`, `for` (failing if the size changes), unpacking, `str()` and `print`; the views from `keys()`, `values()` and `items()`; `set()`, `set(xs)`, `list()` of a dict, set or view, and `sorted()`. The standard library (M6a): `import sys` and `sys.argv`, a module variable built at the import by `pt_argv` (`pythrust-rt/src/sys.rs`); `os.listdir` and `os.path` (`pythrust-rt/src/os.rs`), whose failures raise the `OSError` subclass CPython raises, pending at the call's site. `open`, a file's `read` and `close`, and `bytes` (`len`, `==`, `str`, `print`, held in containers) over one reference-counted runtime object, `PtObj` (`pythrust-rt/src/obj.rs`, slot descriptor `y`); its last reference closes a file. `hashlib.sha256(b).hexdigest()` is one runtime call, `pt_sha256_hex`. Module functions lower to `Rvalue::Std`, one runtime call each (`os.path.join` of more parts, one per part).

Semantics kept from `run`: a read of a variable no assignment has reached fails (`UnboundLocalError` in a function, `NameError` at module level), via a per-variable flag checked unless the read follows an assignment in the entry block or earlier in its own block. A module-level call before the function's `def` raises `NameError`; a call that could reach a function not yet defined is rejected. More than 1000 active calls is a `RecursionError` (the interpreter's `MAX_DEPTH`), counted in the thread's context around each call, so each worker has its own. Defaults are evaluated when the `def` runs, once, so a list default is shared across calls. A function reading a module variable the module has not assigned yet raises `NameError`. An out-of-range string index is an `IndexError` and a repeat too large to allocate a `MemoryError`, as in `run`; so are float division by zero, `**` out of range, a negative `int ** int` exponent, and failed conversions, each with `run`'s message. A message with a run-time part (`could not convert string to float: 'x'`, the `2.0 ** -1` fix-it) is rendered at compile time around a marker, and the runtime fills the marker in (`pt_fail_mid`).

### Exceptions

An exception is a runtime sequence object whose descriptor is `x`, its kind's code (`ir::ExcKind`) as a digit, and its argument's type; its one slot holds the argument. Raising one makes it the runtime's *pending* exception (`pythrust-rt/src/exc.rs`), together with the diagnostic of the place it was raised, rendered at compile time around a marker the runtime fills with `ValueError: msg` if nothing catches it. The IR spells out every step, so codegen only translates:

- After a call to a function whose `raises` set (`infer::Types::raises`) is not empty or that may fault catchably, and after `int(s)` / `float(s)` of a string, lowering tests `Rvalue::Raised` and branches. A call to a function that can do neither costs nothing.
- The catchable faults raise the same way. Codegen's check for `/`, `//` or `%` by zero and for an index out of range (`Rvalue::Index`, `Inst::SetItem`) makes a `ZeroDivisionError` or `IndexError` pending (`pt_raise_msg`) and goes on with a placeholder (a divisor of 1, a null or zero item); lowering tests the flag right after, unless the divisor is a nonzero literal. Codegen fuses such a site with that test: the cold raise branch jumps straight to the test's raise target, so the path that does not raise reads no flag and keeps no placeholder (`FnGen::body`); a call's test stays a flag read. Unpacking's length checks are lowered as raises. Which functions may fault is lowering's own fact (`lower/faults.rs`), never part of `raises`: a division by anything but a nonzero literal, an index into anything but a tuple, an unpacking of anything but a tuple, or a call to such a function, closed over the call graph.
- Inside a `try` body the branch goes to the `try`'s dispatch, after releasing the temporaries of the statements it leaves. The dispatch tests each handler's classes in order (`Rvalue::PendingIs`, one runtime test per handler, a tuple handler's classes in one set of codes); the matching handler takes the exception (`Rvalue::Catch`) into its `as` name, or drops it. No match goes on outward.
- With no `try` left, a function goes to its exit block, which releases every reference it owns, and returns its (ignored) result with the exception still pending: its caller's test sees it. The module's code ends with `Term::Uncaught`, which releases what it owns and prints the diagnostic.
- `except ... as e` unbinds `e` however the handler ends (falling off, `break`, `continue`, a raise caught in the same function), clearing the module mirror too, so a later read fails as in `run`. A name some handler unbinds, a parameter included, is never assumed bound.

The fatal faults (overflow, recursion depth, out-of-memory, `**`) stay `Term::Fail`s and failing rvalues, never caught.

### Strings, lists and tuples

A string is a pointer to an immutable runtime object holding a count, its length in chars (so ASCII strings index in O(1)) and its UTF-8 text. Ownership is decided in lowering and spelled out in the IR, so codegen only translates:

- A string, list or tuple local (`Ty::is_rc`) is null or owns one reference. Operands are borrowed.
- `Retain` adds a reference, `Release` drops one and nulls the local, `Forget` nulls it without dropping (the reference moved).
- Temporaries belong to their statement (a condition counts as one) and are released where it ends. A temporary can be moved out of, which nulls it.
- Assigning a variable takes an owned value (moved from a temporary, or a retained copy), then releases the old one.
- Calls take their reference arguments owned and return an owned result. Every `return` goes through one exit block that releases the function's strings except the result.
- `for x in s` holds its own reference to `s`. Over a list it re-reads the length each time, so appending in the body extends the loop, as in Python. Binding the target is a statement of its own each iteration, so the item, the fields an unpacking reads and the list an indexed target evaluates are released before the body runs.
- A `for` over a list whose loop cannot change it *holds* the list (atomics cost A, Nano 2026-11-02; `lower/hold.rs`): just before the loop starts, `h = Hold(s)` moves the loop's own reference `s` into a new `Ty::Held` local holding one read borrow for the whole loop, whose `len` and reads skip the list's borrow word and whose release drops the borrow, then the reference (`pt_seq_hold`, `pt_seq_len_held`, `pt_seq_get_held`, `pt_seq_release_held`). "Cannot change" is read off the loop's lowered blocks, conservatively: no append, item store, sort or reverse of any list of the walked list's type (another name for it has that type), and no call, Rust binding call, `submit`, `result()` or `map` step, which run code the loop does not show. Any other loop borrows per read, as before, so it still sees what its body appends. The loop's reads and releases of `s` become `h`'s, so code before the hold (filling a temporary the loop walks, which may raise) still releases a plain list. Every way out of the loop (the end, `break`, `return`, an exception) releases the hold. While a hold lasts, other reads of an unmarked list (`xs[0]`, `len(xs)`, a loop that does not hold) take the borrowed path rather than the idle one. Only `build` holds; `check` and `run` analyze the plain list. Fixtures `for_hold` (held and non-held loops, appends during iteration, each exit followed by a change to the list), `for_hold_exits` (held loops nested in `if`, `while` and loops, left from an `else`), `for_hold_aliases` (changes through an optional, tuple, dict, nested list, module list or indexed target, not held), `for_hold_raise` and `for_hold_uncaught` (a task raising while a walked list is filled), and `tasks_unmarked_walk`; `lower::tests` pins which of their loops hold.
- An element a held loop moves into its variable is read without a count (atomics cost B, Nano 2026-11-02; `rc::items`): `Rvalue::Item`, `pt_seq_item_held`, and the variable's releases only null it. The hold keeps the list unchanged and alive, so its elements are too, while it lasts. `rc::elide` decides it with the walk a copy uses to borrow its source (`rc::released_while`), the hold standing for the source: the variable is assigned only there, never retained or copied, never moved, and read only before the hold ends on every path. A store (`append`, a tuple, a dict or set, an optional, an exception) takes its own count of what it stores, so storing the element elsewhere does not stop this: the variable's reference never escapes. Reading it after the loop, copying it to another name or returning it does. Fixture `for_items`, whose uncounted reads `rc::tests` pins; one loop walks a temporary freed, with its elements, when the loop ends.
- `break` and `continue` release the temporaries of every statement they leave, such as a nested `for`'s snapshot when they sit in its `else`.
- `pythrust build` then removes what it proves unneeded (`src/rc/`, phase 4 A7). A parameter the callee never moves, reassigns or releases before its exit, a per-function IR fact (`rc::retains`) where anything opaque counts as keeping, is *borrowed* (`ir::Func::borrowed`): the callee does not drop it, and the caller lends a variable without a copy or releases a temporary itself after the call. A copy released on every path, and read only while its source still holds a reference, borrows from the source instead, across blocks (so `for x in xs` over a variable no longer counts `xs`); a copy of a variable never read again takes its reference instead of adding one. A `Retain` or `Release` of a local null on every path to it goes. Across the corpus this removes 59% of the refcount operations lowering emits (4422 to 1817); `check` and `run` analyze the unelided IR. The `own` summaries do not feed this; the corpus checks the fact against them (A8): a parameter whose summary neither keeps nor returns its lists or strings (`strs`), and which its body never reassigns, is borrowed (`corpus_unkept_parameters_are_borrowed`).

A list or tuple is a pointer to one runtime object: a count, a descriptor, and a vector of 64-bit slots. A slot holds an int, a float's bits, a bool or `None` as 0 or 1, or a pointer the sequence owns a reference to. The descriptor is a prefix code the compiler emits as read-only data (`i f b n s`, `l` and the element, `t`, a field-count byte and the fields, `o` and an optional's present type), which tells the runtime how to compare, print and drop slots. Runtime functions borrow their arguments and give new references, like the string ones. Static types rule out a sequence containing itself, so counts never form a cycle.

A runtime error exits without releasing; nothing else does. A debug build of the runtime counts live strings, sequences and objects (a release build does not: the shared counter contends when tasks allocate, M6c step 4c) and fails a program that ends normally with any still live (`pythrust-rt: N objects leaked`, exit 1), so the native corpus run checks for leaks. With `PYTHRUST_VALGRIND=1`, `corpus_matches_native` also runs every native program under valgrind's memcheck and fails on invalid reads, writes or frees, on definitely lost blocks, and on any instrumented run that does not finish as its golden says or whose log lacks memcheck's clean `ERROR SUMMARY: 0 errors` line (so a valgrind that cannot start, is killed or times out fails too); CI's `memcheck` job does this on x86-64 Linux.

Everything else is a compile error, `backend error: the native backend does not support X yet`, pointing at X. Nothing is guessed. `corpus_matches_native` in `tests/conformance.rs` builds every corpus program, runs what builds against its golden, and requires the programs in `NATIVE` to build.

## Choices made inside the settled design

- **Recursion limit matches `run`** (1000 active calls), as Nano chose; it is one constant.
- **`Retain`/`Release`/`Forget` instead of ir.md's `Copy`/`Move` operands with `RcInc`/`Drop`.** The same information: a move is a `Use` then a `Forget`, a copy a `Use` then a `Retain`. Keeping operands plain kept every existing int rvalue unchanged, and M5's ownership pass can still delete the pairs it proves unnecessary.
- **Numeric semantics are copied into the runtime, not shared with the interpreter.** Float `repr`, floor division, `**` and number parsing exist in `interp` and in `pythrust-rt/src/num.rs`. Sharing them needs a crate both depend on (the runtime cannot be a library of the compiler: it defines `main`). The copies are small and the native corpus test holds them to the same output; a shared crate is a follow-up if they grow.
- **Exceptions are a pending slot, not a second return value.** ir.md planned for a call to return a tag plus value. The tag lives in the runtime instead, as a flag byte in the thread's context that generated code reads inline with one load, through one codegen helper (`FnGen::pending_flag`); the IR branches on it after each call that may raise, exactly where a returned tag would be tested. This keeps every signature and the C ABI unchanged on all four targets (no multi-value returns), and a callee that cannot raise costs its caller nothing.
- **Per-thread state is a hidden first parameter** (M6c). Every generated function takes the thread's context, `PtCtx` (`exc.rs`: the pending flag at offset 0, the call depth at 8), as its first argument and passes it on; `main` gets it from `pt_ctx()`. Cranelift's thread-local support would call `__tls_get_addr` on some targets, while a parameter costs a register move; the benchmarks moved by at most 0.4% in instruction counts.
- **Counts are atomic only once marked** (M6c, [research/concurrency.md](research/concurrency.md) rule 3). A count or borrow word's top bit is the mark; an unmarked one changes by plain loads and stores, a marked one by atomic read-modify-writes (`sync.rs`). `pt_mark` walks a value and everything it reaches once, and a store into a marked container marks what it stores, so everything a marked value reaches stays marked. A copying read, swap or append on an unmarked, unborrowed list skips the borrow word, which keeps every benchmark within the 3% gate. A borrow conflict on a marked value ends the program as a runtime bug: rule 4 should have rejected it. `print` reaches stdout a whole line at a time, so lines from tasks never mix; only a single line longer than 64 KiB, published in pieces to bound memory, can.
- **Tasks run on the executor's workers** (M6c step 4b). The `with` statement owns its executor as a temporary of type `Exec` (`pt_exec_new`); releasing it is `pt_exec_end`, which waits for every task, so the block's end, `break`, `continue`, `return` and an exception leaving it all wait, as CPython's `shutdown(wait=True)` does (fixture `tasks_leave_block`). `ex.submit(f, *args)` is `Rvalue::Submit`, which borrows its operands. Codegen marks each argument and every module value the task's function, or anything it calls or submits, loads or replaces (`codegen::task::reads`), gives the task a reference to each argument, and calls `pt_submit` with a per-function thunk that unpacks the slots, calls the function with the worker's context and drops the arguments the function borrowed. A future is a `Future` handle; a list of futures has the descriptor `lu`. `fut.result()` is `Rvalue::TaskResult`, followed by the raise test when a task may raise. What crosses to a worker is only what was marked, plus the outcome, handed back under the future's lock (`pythrust-rt/src/task.rs`). Marked values pay atomics on every count change and borrow: about 20 ns per `inc`+`dec` pair and per borrow, against 1 to 2 ns unmarked, and 3.5x on a benchmark that walks a list a task was given, 1.6x once a loop holds the list ([benchmarks.md](benchmarks.md#shared-values-m6c)). `ex.map(f, xs)` submits a task per element of `xs`, read once, and gives its results as `Ty::Results`: a list of their futures (descriptor `lu`), reversed once made (`pt_list_reverse`), so each step takes the next from its end (`Rvalue::NextResult`, `pt_results_next`), waiting for its task. A `for` over the results, `in`, and `list`, `sorted` and `set` take results while any are left, so they are taken once and in order; `in` stops at the first equal one, and a task's exception ends them, dropping the futures not yet taken, as CPython's `map` iterator does (fixture `tasks_map_taken`). The results are always true, as a generator is.
- **Races are checked by ThreadSanitizer** (CI's `race` job, x86-64 Linux). The runtime and the standard library are instrumented (`-Zbuild-std`), and with `--cfg pythrust_tsan` each change of an unmarked count or borrow word, and each use of an idle slot's fast path, is reported as the plain write it stands for, so two threads using one unmarked value is a reported race, even when both only read it; without that the detector never sees one, since those words are relaxed atomics. `TSAN_OPTIONS=history_size=7` is needed: with the default, a race against an access far back in the other thread's history is dropped, not reported, because its stack cannot be restored. Each task program in the corpus runs 5 more times pinned to one CPU and 5 unpinned (`PYTHRUST_TSAN_RUNS`). A fault in a task exits without joining the workers, which the detector would report as leaked threads, so a fixture marked `# native-unjoined:` (only `tasks_map_break`) runs with `report_thread_leaks=0`. Every other program must have joined them, including one an uncaught exception ends, since leaving the `with` joins them. Calibration gate (`the_race_detector_reports_injected_races`, pinned to one CPU; Nano, 2026-11-02): a runtime built with `--cfg pythrust_calibrate` injects the race `PYTHRUST_FAULT` names, and each fixture must be reported with it and clean without: `outcome`, the worker changing an unmarked result's count after handing it over, the race of step 4a (`tasks_result_released`); `late-free`, the worker freeing a marked result after handing it over (`tasks_result_marked`); `unmarked`, no value ever marked, and `nonatomic`, marked counts changed by plain loads and stores (both `tasks_unmarked`); and `unmarked` again on `tasks_unmarked_walk`, where both threads walk an unmarked `list[int]` in held loops, so the holds are the only shared writes (atomics cost A). Locally each was reported in 20 of 20 runs pinned and 0 of 20 without the fault; one manual unpinned measurement on 4 CPUs reported each in 50 of 50. `tasks_unmarked` was reported in 10 of 10 by the borrow-word hook alone. After holds (A), all five were reported in 20 of 20 pinned runs of the gate, and a variant of `tasks_unmarked_walk` in which each thread enters its held loop once was reported in 20 of 20 pinned with the fault and 0 of 20 without. Under the detector a last `dec` orders the free with an acquire load, as std's `Arc` does there, since the detector cannot see a standalone fence (`tasks_values` caught that false report). Cranelift's generated code is not instrumented, so what it loads and stores itself (module values, the thread's context) is unchecked; runtime calls on them are. Helgrind was tried first and is unusable here: it cannot see the standard library's futex-based `Mutex`. MSVC has no ThreadSanitizer, and AArch64 Linux and macOS are not wired up. Memcheck covers the same fixtures in its own job.
- **Fallible runtime calls report a status byte** through a stack slot rather than returning a pair, which keeps the C ABI to scalars and pointers.
- **Module variables functions read are mirrored, not moved.** The module's code keeps such a variable in a local, as before, and each assignment also stores it (with a bound flag) in a module-private global, which holds its own reference. Functions only read the global: they cannot assign module variables without `global`, which the subset reserves. Module-level loops therefore stay on locals. Only names some function refers to get a mirror. A default is a global of its own, stored when its `def` runs. The module's end drops what the globals own, so the leak check still sees zero.
- **Tuples are boxed**, not unboxed as planned: one runtime object like a list, so a tuple in a list slot, a tuple argument and a tuple result need no multi-value ABI. A tuple's fields are read by literal index (inference requires one), so unboxing stays an optimization M5 can make without changing the IR's types. Nano accepted this on the condition that the layout stays out of every ABI (`pythrust-rt`'s C surface and future Rust interop see no tuple representation), and asked for a tuple-heavy benchmark to measure its allocation cost.
- **A `range` value is a runtime sequence of its three bounds**, `start`, `stop` and `step`, with its own descriptor so `len`, indexing, `in`, `==` and `repr` see the ints it produces (`pythrust-rt/src/range.rs`, mirroring the interpreter). `for` over a range value reads its bounds once and loops like `for x in range(...)`, which still allocates nothing. A length beyond `i64` fails `len` with an `OverflowError` and unpacking with "too many values", as in `run`.
- **List and tuple types are interned** in `Program::types`, so `ir::Ty` stays `Copy`. An empty list whose element type nothing constrains (`not []`) gets `None` slots; it never holds an element.
- **An optional is one nullable reference**, as Nano chose: null is `None`; a present string, list or tuple is that pointer; a present int, float or bool is boxed in a one-field tuple. One layout everywhere (locals, slots, arguments, globals) reuses the sequence runtime and reference counting, at the cost of an allocation per present scalar. Lowering wraps a value where an optional is expected and unwraps a read inference narrowed; a tuple display whose fields are narrower than its declared type (`(None, 4)` for `tuple[str | None, int | None]`) is rebuilt as that type.
- **Dicts and sets are sequences with an index** (M6). A dict is a `pythrust-rt` sequence whose slots alternate keys and values in insertion order, a set one whose slots are its elements; beside them an open-addressing index (linear probing, at most half full) maps a key's hash to its entry. Hashing agrees with the runtime's equality, so `1` and `True` are one key; a `bool` stored in an `int`-keyed dict or set is stored as its int, as in `run` (grammar.md, Deviations). Nothing is ever removed, since the subset has no `del` yet, so an entry's place is its insertion order and iteration walks the slots. A view (`d.keys()`) is a snapshot sequence, as in `run`; `for k in d.keys()` and `x in d.keys()` skip the view and use the dict directly. A `for` over a dict or set reads its size once and tests it at each step, failing with CPython's `RuntimeError` message, as `run` does.
- **`None` has no machine value.** A function returning `None` returns nothing. (ir.md: zero-sized.)
- **Monomorphization from signatures.** An instance's type variables are bound by matching the generic signature against the call's argument and result types. In generic code a call's result type may be open: the signature does not fix it (`def square(n): return n * n` has a result variable of its own), and the call's node type is in the callee's variables. Such an instance is lowered at the call, and its first `return` decides the result type in the declared shape (inference made every `return` agree; `[x * x]` from a `-> list | None` function makes it `list[int] | None`) and binds the signature's result variable, so later recursive calls resolve; the caller binds the call's own open variables from it too. A display whose item types are open (`[n * n]`) binds them from its lowered items. A statement that needs a result not yet known (a call back into an instance being lowered, directly or through another open instance, or a `return None` whose optional is still open) is skipped, and the instance is lowered again once a `return` has decided (`rec(n - 1, x) + x` before `return x * x`). A conditional expression whose type is still open takes it from the branch that lowers, so `h(n - 1, x) if n else x * x` decides from `x * x` though the statement is skipped. An instance no `return` decides on its own, because every `return` needs its own result (it never returns), returns `None` into an open optional, or there is no `return` (a `-> list | None` function that only returns `None`), is *settled*: each open variable of its result takes what the body bound it to, else `None` (so `list[None] | None`, as `not []` gets), and it is lowered again with that type. No value of that type is ever produced, so the type is sound for the value. A settled instance with no path out at all *never returns*: every `return` waits on its own result (directly, or through an instance that waits on it and has no way out either) and the end of its body is unreachable. Lowering a call into one ends the path there, unreachable, so the operation on its result (`return f(n - 1) + 1`) and the rest of its block are never lowered, and the call fails as in `run`, with `RecursionError`. Only the path ends: the other branch of a conditional expression, the short-circuit of `and`/`or`, the stopping link of a chained comparison (`0 > 1 < f(1)` is `False`), and the earlier branches of an `if` whose `elif` test never returns carry on. An `and`/`or` whose type is still open takes it from its left operand, so `f(n - 1) or f(n + 1)` is found never to return too. What such a call binds is kept apart: it types only values that never exist (a variable only it assigns), so the branch that returns still decides (`spin(n) if n else x * x` is an `int` for an `int` `x`). A variable, a conditional expression or an `and`/`or` is never typed from such a call, nor before its type is settled (no variable left anywhere in it, so `[x * x]` in generic code waits for its element, decided by an assignment's live value or the branch that lowers; the `None` an unconstrained element defaults to, as in `not []`, is no such decision): one first met before live code types it (a read in an earlier branch, or in a loop before its assignment) skips its statement, and the body is lowered again once the rest has been seen, with the type a live assignment gave it, or, if none did, as never assigned, so every read of it fails as unbound (`NameError` or `UnboundLocalError`, as in `run`). A module variable only such assignments assign (the statement cut short and the rest of its block, which is never lowered) fails the same way when a function reads it before the module has typed it; a later module assignment to it is then a backend error rather than a guess. The analysis stays conservative: a skipped statement that could still complete another way (a stuck branch whose other branch lowers, a callee that may return `None`) counts as returning, and such an instance is settled as before. An instance whose every `return` waits on a caller still being lowered is not settled, because that caller may yet decide (`pong` calling back into `ping`); it is lowered again when called once more. If such an instance reaches a call that cannot be skipped, it stays a backend error; no known program does. Inference exposing per-instance types, as ir.md anticipated, would replace this.
- **`target-lexicon` as a direct dependency** for the host triple. It is already a dependency of the accepted `cranelift-*` crates, so no new crate enters the tree. `cranelift-native` (CPU feature detection) is left out so binaries run on any machine of the same architecture.
- **Runtime lookup next to the compiler**, because Cargo cannot yet express "this binary needs that static library" (artifact dependencies are unstable). The conformance test builds `pythrust-rt` itself, with the profile and target of the `pythrust` under test, since `cargo test` does not.
- **Objects are written to a fresh build directory beside the executable**, created exclusively and removed after linking. The object becomes the executable, so it gets the same protection: whoever could swap or read it there could swap or read the output. The system temp directory would promise more than it holds, since `TMP` may name a shared directory and Windows has no owner-only mode short of writing an ACL. On Unix the directory is also mode 0700.
- **MSVC on Windows**, Rust's default Windows toolchain, so the runtime, the compiler and the linker agree without a GNU toolchain. `link.exe` is found with `find-msvc-tools` (cc-rs, no dependencies of its own, built only on Windows) as rustc finds it: a developer prompt's `PATH`, else the newest installed Visual Studio, so a plain shell works. It links the system libraries `rustc --print native-static-libs` lists, with the dynamic C runtime (`msvcrt.lib`), whose `mainCRTStartup` calls the runtime's `main`. Linker output is shown on failure, since `link.exe` reports errors on stdout.
- **Linking drops unreached code and debug info**, as Cargo's release profile strips debug info by default: `--gc-sections` and `--strip-debug` on Linux, `-dead_strip` and `-S` on macOS, and on Windows `/OPT:REF` and `/OPT:ICF` (MSVC writes debug info only with `/DEBUG`, so there is none to strip, and no PDB, so a panic backtrace there has no symbol names). On x86-64 Linux a benchmark program went from 5.5 MB to 0.44 MB with a release runtime (6.3 MB to 0.46 MB with a debug one): about 4.1 MB was the standard library's debug info and most of the rest unused standard-library code. Those numbers are Linux measurements only; on macOS and Windows, `corpus_matches_native` in CI is the only check. Symbols stay, so a runtime panic still has a readable backtrace. `corpus_matches_native` fails any corpus binary over 1 MiB on every CI target, or over 2 MiB for a program using tasks, which links the runtime's threads: `tasks_map` and `tasks_map_taken` are 1.05 to 1.12 MB on AArch64 and macOS (Nano, 2026-11-02), still far below the 5 MB the bound catches. Of the remaining 0.3 MB of code on Linux, about 0.17 MB is the standard library's backtrace symbolizer, which only a `no_std` runtime or a rebuilt standard library would remove.

## Benchmarks

M4's four benchmarks are in `bench/`, with results and analysis in [benchmarks.md](benchmarks.md). Scalar code runs about 20x faster than CPython, list sorting about 8x, string building about the same, and tuple-heavy code about 1.8x; a tuple-free control of the same work runs about 6.8x faster than the tuple version, most of it plausibly boxed tuples (see the confounders there).

## Known gaps

- **An exception holding a list of exceptions** (`ValueError([ValueError(0)])`, or a tuple or optional holding such a list) is a backend error. It is the one value whose reference counts could form a cycle (`xs.append(e)` with `e = ValueError(xs)`), which refcounting would leak and whose `repr` needs Python's `[...]`. Any other value is acyclic: a value is built from values that already exist, so a cycle needs a list changed afterwards to reach back to it, and only an exception hides its argument's type, so the last exception before that list on a cycle holds, by its argument's type, a list whose elements may hold an exception. `codegen::may_cycle` is that test; every other exception holding a list (`ValueError([1])`, `IndexError([['a']])`, `ValueError(([1], ValueError(0)))`) builds. Any exception-typed value counts, whatever its kind (so `list[Exception]` from B4), and a future `dyn` must count as one. `check` and `run` accept these programs; `build` fails at the construct, saying native code has no cycle collector (Nano, 2026-10-29). It lowers, so the `own` stage sees it (as keeping the list). A dict whose values, or a set whose elements, may hold such a list counts the same way (M6), and so does a view of one; keys never can, being hashable. Closing it needs a cycle collector in `pythrust-rt`.

- **A bool stored as a key of an int-keyed dict or set inside a generic function** (`def put(d, k): d[k] = 1` called with `True`) is a backend error. Native code stores the int, but `run`, the reference, does not specialize generic code and may still show the key as `True` there, so `build` refuses rather than differ (Nano, 2026-10-31). The same store outside generic code builds. Fixture `dict_bool_key_generic`.
- **A `sum` of floats with no `start` inside a generic function** (`def boxed(xs): return [sum(xs)]` called with a `list[float]`) is a backend error, even when the list is not empty. Native code would give an empty one as `0.0` (D50), but `run`, the reference, does not specialize generic code and gives the int `0`, as CPython does, so `build` refuses rather than differ (Nano, 2026-11-04, D59). The same `sum` outside generic code builds. Fixture `builtin_sum_empty_float_generic`.

M4 closed with these open; [roadmap.md](roadmap.md#phase-3-native-status-m4-done) tracks them as follow-ups. Generic functions where no `return` decides the result type, the other M4 follow-up, now build, including operations on the result of one that never returns (see the monomorphization note above).

- **Targets:** CI declares x86-64 and AArch64 Linux, macOS and Windows (MSVC), one native runner each, since codegen targets the host and links with the host linker. The added x86-64 macOS (`macos-15-intel`) and AArch64 Windows (`windows-11-arm`) lanes use [standard GitHub-hosted runners](https://docs.github.com/en/actions/reference/runners/github-hosted-runners), not larger paid runners. Each lane selects its Rust host and CPython 3.13 architecture explicitly; `ci/check_host.py` fails before tests if the runner OS/architecture, Python process architecture/bitness or either Rust tool's host disagrees. `cargo test --locked` includes the debug native corpus, followed by the same corpus through the release compiler and runtime. The `all` gate still requires every matrix lane and every other job to succeed. Prior native validation covers x86-64/AArch64 Linux, AArch64 macOS and x86-64 Windows; the two added targets require a successful hosted CI run of these checks before being called validated. Local Linux checks do not validate either added target. The Windows GNU toolchain (MinGW) is not supported and remains unvalidated.
- **Diagnostics:** for a native program that fails, `corpus_matches_native` requires its stderr to equal `run`'s byte for byte (message, location, carets). CI checks this on every target above.
