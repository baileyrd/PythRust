# Roadmap

Each phase ends in something runnable.

1. **Spec.** Formal grammar for loose syntax. Exact syntax for tempering annotations, pause markers, and the shared-lock keyword. Precise enough to write a parser.
2. **Vertical slice.** Parser and type inferencer in Rust for a small subset (functions, numbers, strings, lists, control flow). Interpreter first, to prove the loose syntax feels right.
3. **Native backend.** Cranelift (decided). Generate native code for the subset. Benchmark against Python.
4. **Core differentiators.** Ownership inference, borrow checking, tempering, exception-to-Result error lowering. The hardest phase.
5. **Ecosystem.** Python typed bridge, Rust binary-level interop, unified package tool (one manifest, one lockfile), concurrency.

Concurrency and interop come last because they depend on everything beneath them.

Gut estimate: phases 1-3 (a prototype) about a quarter; a language trusted for real work, one to two years.

## Phase 4 (M5) plan

Language decisions D1 to D8 are in [grammar.md](grammar.md#phase-4-m5-tempering-ownership-exceptions-nano-2026-10-27) (Nano, 2026-10-27). Exit (from [handoff.md](handoff.md)): a tempered function rejects what a loose one accepts, with diagnostics a Python programmer can act on, and no leaked borrow-checker vocabulary. One PR per item, in order within a track; track B needs only A1, and A6 waits for B3.

Track A, tempering and ownership:

- [x] **A0. Generic results no `return` decides** build natively (#36), so lowering covers nearly every checked program. The ownership analysis runs on the IR; the remaining gap above (an operation on a never-returning generic result) must be closed or handled before A3 relies on lowering.
- [x] **A1. Tempered signatures (D1, D5).** Required annotations, no `dyn`, tempered calls only tempered functions and builtins. Corpus property: removing `temper` from a passing program leaves its output unchanged; the harness runs CPython on loosened programs and `tempered_matches_loose` checks Pythrust too.
- [x] **A2. `list(xs)` copy builtin (D3, D4)** in inference, interpreter and native (#38): a shallow copy of a list only (other iterables are a recorded deviation), natively the runtime call `pt_list_copy`.
- [x] **A3. Parameter mode inference.** Wire `check` and `run` through lowering (analysis only; `run` still interprets), behind a coverage gate: every program `check`/`run` accepts today keeps passing, so a lowering gap is never a new language restriction. A function lowering cannot express gets a conservative summary (every parameter `owned`, result may alias any parameter), which is sound for loose code. Known gaps to keep as regression fixtures: a call to a builtin before the `def` that shadows it (`x = print(7)` then `def print(n): return 1`, rejected in `lower/expr.rs`), an operation on a never-returning generic result, and `try`/`raise` until B3. Then an `own` stage over the IR: per-function `read`/`mut`/`owned` per parameter and whether the result aliases one, bottom-up with a fixpoint per strongly connected component. No user-visible change. Done in the `own` stage (`own::analyze`): a flow-insensitive points-to analysis over abstract lists (each parameter with the lists inside it, the module's values, one per allocating local), with the call graph solved as one least fixpoint, the same answer per strongly connected component. Only list-holding values are tracked; any other parameter is `read`. `Mode::Owned` means kept past the call other than as the result, which is `result_aliases`; ownership.md's `owned` is either. The fallback is whole-program, since lowering fails at its first gap. B3 closed the `try`/`raise` gap; A6 closed the last one, an exception holding a list, which lowers and only the native backend rejects. `corpus_ownership_coverage` holds the gate: every `NATIVE` program is precise, and the only fallbacks are named backend gaps (none in the corpus since B3).
- [x] **A4. Mode syntax (D2).** Parse contextual `mut`/`owned`; check written modes against inferred ones; tempered functions must write them. Mode diagnostics come only from precise summaries, never from A3's conservative fallback: for a body that does not lower yet, checking its modes waits until it lowers. Done in `own::check`, run by `check`, `run` and `build` alike (`corpus_errors_fail_build` holds `build` to every compile error). Analysis now lowers every function whose signature is concrete, called or not (`lower::lower_every`), so an uncalled tempered function is checked; `build` still compiles only what runs. B3 left `try`/`raise` precise (`a_body_with_try_and_raise_is_checked`). Over-declaring a mode is allowed, as for `raises`. Corpus `modes`, `modes_unwritten`, `modes_too_weak`.
- [x] **A5. Loose call-site aliasing.** `f(xs, xs)` against a `mut` parameter of a **tempered** callee is an error about the call ([ownership.md](research/ownership.md#decided)). Loose-to-loose calls keep Python aliasing, even when the loose callee writes its modes. Done in `own::calls`, from precise analyses only, against the callee's written `mut` and `owned` (its contract; A4 holds the body to it), for every caller, tempered included. A function that passes its parameters on to such a contract takes it on as a *need* (two parameters, or one and the module's values, share no list), settled up the call graph to a fixpoint, so `forward(a, a)` fails when `forward(xs, ys)` calls tempered `push(xs, ys)`; a body is analyzed as if its parameters held unrelated lists, so a function with needs also needs every parameter it stores a list into (and the module's values, when the body can see them) unshared with the others, or a store through one could show through another unseen. Loose aliasing that never reaches a tempered contract is untouched. "May pass one list" is a flow-sensitive points-to pass over the CFG (`body::shared_args`): an assignment replaces its local's lists and a reallocated local is a new list, so `add(rows, row)` then `row = [2]` then `add(rows, row)` passes, while `rows.append(row)` before `add(rows, row)`, or the same call twice in a loop, fails. Known imprecision, both erring toward the error: elements of one list are not told apart (`f(rows[0], rows[1])`), and module variables a function reads count as one list, since the module's code may have stored one in another. Corpus `modes_shared_call`.
- [x] **A6. Tempered body checks (D3, D4).** Non-lexical alias check over the CFG, diagnostics in Python terms. Needs every tempered body to lower: lands after B3 so tempered `try`/`raise` lower, and closes any other lowering gap a tempered body can reach instead of rejecting it. Done in `own::alias`, run by `own::check` before a tempered function's modes: a forward pass over the CFG gives each local the lists it may be (strong updates, an allocation's latest run told apart from earlier ones, a type inside each abstract list so an element is not its container: one list has one type), over the summaries' flow-insensitive heap; a backward pass gives which locals are still used. A temporary changed or still used counts through the variable it was read from, except a `for` loop's sequence. A probe of tempered strings, floats, tuples, optionals, `while`, `for`, defaults, conditional expressions and `try`/`raise` found no further lowering gap; the one left, an exception holding a list (`ValueError(xs)`), now lowers: only the native backend rejects it (`codegen::refuse_gaps`), so the analyses see it, and holding a list in an exception keeps it (`owned`), since the exception may outlive the call. Inside a value from elsewhere (a parameter, a global, a call's result) any two places of one type may be one list (`(xs, [xs])`); a tuple the body built keeps its fields apart; a parameter may be a global's list (`f(saved)`), while two parameters are kept apart by A5; a module variable read later, directly or by a callee, is a name still used, and a callee's change to a module's list (transitively) is a change at the call. Corpus `aliasing`, `aliasing_shared`, `aliasing_return`.
- [x] **A7. Refcount elision in native.** Use the summaries and last-use analysis to drop `Retain`/`Release` pairs; rerun the benchmarks and valgrind the corpus. Done in `rc::elide`, an IR-to-IR pass `build` runs between lowering and codegen ([native.md](native.md#strings-lists-and-tuples)): borrowed parameters, copies cancelled within a block, and releases of locals null on every path. It reads an IR-level fact, not the `own` summaries (Nano, 2026-10-29): `rc::retains`, per function, the parameters whose reference it may keep or give up, computed once from its own body. Lowering passes a variable to a call as a retained copy, so what a callee keeps is the copy's reference and the fact needs no call-graph order or fixpoint. Anything the pass cannot see through counts as keeping: every instruction and rvalue is classified by an exhaustive match, so a future channel send, indirect call or Rust or Python bridge keeps until classified. Corpus `refcount_keeps` covers a callee storing, returning, boxing and raising its argument. 55% of the corpus's static refcount operations go (#50); the follow-ups (a copy borrowing across blocks, the `for` snapshot of a variable among them, a copy at its source's last use taking the reference, and `pt_seq_dec` without an allocation) take the corpus from 4422 to 1817 operations, against 1951 after #50. The native corpus stays leak-free and clean under memcheck (`refcount_keeps`, `refcount_moves`). Benchmarks ([benchmarks.md](benchmarks.md#refcount-elision-a7)): `sorting` about 5% faster, `tuples` about 13%, the rest flat, since their time is in allocation and runtime calls.
- [ ] **A8. Summaries for every reference-counted type.** The `own` summaries track lists, including lists inside tuples and optionals (`own::holds_list`), so a `tuple[list[int], int]` or `list[int] | None` parameter can be `mut` or `owned`. What they do not describe is the reference ownership and lifetime of a value holding no list: a string, a tuple or optional of non-list values, or an exception is always `read`, even when the function stores or returns it. Extend the vocabulary to those effects (whether the function keeps such a value past the call), keeping the list analysis as it is, before tempering relies on it beyond lists. Then check A7's IR-level fact against the summaries rather than feeding it from them: a corpus test that a parameter the summaries call `read`, not returned and never reassigned, is borrowed by `rc::elide`. The IR fact stays the source for refcounts, since it is exact and the summaries are joined across a generic function's instances.
