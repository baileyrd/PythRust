# Roadmap

Each phase ends in something runnable.

1. **Spec.** Formal grammar for loose syntax. Exact syntax for tempering annotations, pause markers, and the shared-lock keyword. Precise enough to write a parser.
2. **Vertical slice.** Parser and type inferencer in Rust for a small subset (functions, numbers, strings, lists, control flow). Interpreter first, to prove the loose syntax feels right.
3. **Native backend.** Cranelift (decided). Generate native code for the subset. Benchmark against Python.
4. **Core differentiators.** Ownership inference, borrow checking, tempering, exception-to-Result error lowering. The hardest phase.
5. **Ecosystem.** Python typed bridge, Rust binary-level interop, unified package tool (one manifest, one lockfile), concurrency.

Concurrency and interop come last because they depend on everything beneath them.

Gut estimate: phases 1-3 (a prototype) about a quarter; a language trusted for real work, one to two years.

Parameter mode inference.** Wire `check` and `run` through lowering (analysis only; `run` still interprets), behind a coverage gate: every program `check`/`run` accepts today keeps passing, so a lowering gap is never a new language restriction. A function lowering cannot express gets a conservative summary (every parameter `owned`, result may alias any parameter), which is sound for loose code. - [x] **A5. Loose call-site aliasing.** `f(xs, xs)` against a `mut` parameter of a **tempered** callee is an error about the call ([ownership.md](research/ownership.md#decided)). Loose-to-loose calls keep Python aliasing, even when the loose callee writes its modes. Done in `own::calls`, from precise analyses only, against the callee's written `mut` and `owned` (its contract; A4 holds the body to it), for every caller, tempered included. A function that passes its parameters on to such a contract takes it on as a *need* (two parameters, or one and the module's values, share no list), settled up the call graph to a fixpoint, so `forward(a, a)` fails when `forward(xs, ys)` calls tempered `push(xs, ys)`; a body is analyzed as if its parameters held unrelated lists, so a function with needs also needs every parameter it stores a list into (and the module's values, when the body can see them) unshared with the others, or a store through one could show through another unseen. Loose aliasing that never reaches a tempered contract is untouched. "May pass one list" is a flow-sensitive points-to pass over the CFG (`body::calls`): an assignment replaces its local's lists and a reallocated local is a new list, so `add(rows, row)` then `row = [2]` then `add(rows, row)` passes, while `rows.append(row)` before `add(rows, row)`, or the same call twice in a loop, fails. Known imprecision, both erring toward the error: elements of one list are not told apart (`f(rows[0], rows[1])`), and module variables a function reads count as one list, since the module's code may have stored one in another. Private named-global may-store summaries also propagate a loose callee's stores into module call sites, including captured globals, argument-to-global stores, aliases and recursive call chains. They resolve against the module's current bindings; later stores and fresh rebindings stay separate. Corpus `modes_shared_call`, `modes_callee_global_store`, `modes_callee_parameter_store` and CPython/native-checked `modes_callee_disjoint`; CLI regression `loose_callee_stores_reach_tempered_call_checks`.
- [x] **A6. Tempered body checks (D3, D4).** Non-lexical alias check over the CFG, diagnostics in Python terms. Needs every tempered body to lower: lands after B3 so tempered `try`/`raise` lower, and closes any other lowering gap a tempered body can reach instead of rejecting it. A temporary changed or still used counts through the variable it was read from, except a `for` loop's sequence. Computed receivers retain each possible source separately across conditional and `and`/`or` joins, including projections and unattributed call/fresh alternatives; one source never exempts another live alias (Issue #71, Mill Board #801). A probe of tempered strings, floats, tuples, optionals, `while`, `for`, defaults, conditional expressions and `try`/`raise` found no further lowering gap; the one left, an exception holding a list (`ValueError(xs)`), now lowers: only the native backend rejects it (`codegen::refuse_gaps`), so the analyses see it, and holding a list in an exception keeps it (`owned`), since the exception may outlive the call. Inside a value from elsewhere (a parameter, a global, a call's result) any two places of one type may be one list (`(xs, [xs])`); a tuple the body built keeps its fields apart; a parameter may be a global's list (`f(saved)`), while two parameters are kept apart by A5; a module variable read later, directly or by a callee, is a name still used, and a callee's change to a module's list (transitively) is a change at the call. Corpus `aliasing`, `aliasing_shared`, `aliasing_return`, `aliasing_conditional`, `aliasing_or`, and the CPython/native legal control `aliasing_join_disjoint`.
- [x] **A7. Refcount elision in native.** Use the summaries and last-use analysis to drop `Retain`/`Release` pairs; rerun the benchmarks and valgrind the corpus. Done in `rc::elide`, an IR-to-IR pass `build` runs between lowering and codegen ([native.md](native.md#strings-lists-and-tuples)): borrowed parameters, copies cancelled within a block, and releases of locals null on every path. It reads an IR-level fact, not the `own` summaries (Nano, 2026-10-29): `rc::retains`, per function, the parameters whose reference it may keep or give up, computed once from its own body. Lowering passes a variable to a call as a retained copy, so what a callee keeps is the copy's reference and the fact needs no call-graph order or fixpoint. Anything the pass cannot see through counts as keeping: every instruction and rvalue is classified by an exhaustive match, so a future channel send, indirect call or Rust or Python bridge keeps until classified. Corpus `refcount_keeps` covers a callee storing, returning, boxing and raising its argument. 55% of the corpus's static refcount operations go (#50); the follow-ups (a copy borrowing across blocks, the `for` snapshot of a variable among them, a copy at its source's last use taking the reference, and `pt_seq_dec` without an allocation) take the corpus from 4422 to 1817 operations, against 1951 after #50. Benchmarks ([benchmarks.md](benchmarks.md#refcount-elision-a7)): `sorting` about 5% faster, `tuples` about 13%, the rest flat, since their time is in allocation and runtime calls.

### Diagnostic follow-up #804

D3 still rejects returned parameter aliases, including nested containers and
already shallow-copied nested lists. Its copy hint is now restricted to returned
lists whose elements contain no mutable containers; named hints copy the actual
returned local. Ownership regressions cover nested list/tuple/dict/set/Optional
shapes and applied flat-list fixes. The CLI regression checks identical rejection
through `check`/`run`/`build` and executes the fixed conditional flat-list return
in the interpreter and native code. Related to issue #73 item 2; its other
findings are not declared resolved by this card.


### Native string-chain experiment #807

A bounded native prototype fuses an adjacent, single-use unnamed concat prefix
only when its tail is an unchanged borrowed string parameter (D64). It preserves
operand work/check order and ordinary ownership/exception cleanup; all uncertain
shapes retain binary concat. Empty/Unicode/alias, side-effect/exception and shared
worker regressions accompany deterministic overflow and allocation-failure probes.
[Same-host evidence](benchmarks.md#adjacent-native-string-chains-807) shows one
result object/buffer for a nonempty triple and fewer copied bytes; the existing
string workload remains unaffected. This is an experiment awaiting independent
review and required CI, not #808 work or a broader language milestone. #767's
mapping, #806, held #396/PR #119 and open issue #73 are unchanged.


### Portable SHA-256 pilot #809

One safe scalar 16-word circular schedule with expanded rounds preserves D22,
SHA-256 digests, padding/wrapping length behavior, whole-file reads, dependencies
and public/runtime/binding ABIs. The interpreter and native runtime share its
source. [Fresh measurements and correctness evidence](benchmarks/card809.md)
support retaining this bounded variant for independent review and required CI:
loaded-SHA medians fall 25–28% and full large-file fclone medians 20–30% on warm
synthetic tmpfs fixtures on one host. This is not an OpenSSL parity or general I/O
claim, nor completion of #810/#811, a language milestone or #396/PR119.
